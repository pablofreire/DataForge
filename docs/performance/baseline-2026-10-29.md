# k6 baseline: 2026-10-29

**What was measured:** authenticated, read-heavy API traffic from the customer portal:
- `GET /api/projects`
- `GET /api/jobs?limit=20`
- `GET /api/auth/me`

**Script:** [`tests/k6/scenarios/baseline.js`](../../tests/k6/scenarios/baseline.js)
**Raw summary:** [`tests/k6/results/baseline-10vus.json`](../../tests/k6/results/baseline-10vus.json)

## Environment

| Item | Value |
|---|---|

## How to read these numbers

- **Best-case latency.** The load generator and the application share one machine and the Docker network. There is no TLS and no network hop between them, so these figures are not production latency.
- **Small data.** The demo tenant holds tens of projects. This baseline checks request-path overhead (authentication, tenant resolution, Dapper queries, JSON envelope), not query cost at scale.
- **Clock artifact.** k6 reported a negative minimum duration on 2 of 266,018 requests. This is a Docker Desktop VM clock artifact. It does not change any percentile.
